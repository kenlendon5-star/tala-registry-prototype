## Implementation

- Foreground coarse/fine permissions are requested only after choosing Capture device location on the household Overview. No Internet, background location, Play Services or map dependency was added.
- Injectable framework location acquisition accepts a measurement newer than the request, preserves the provider's original capture time and accuracy, and stops after a result, cancellation or 20-second timeout. Navigation, backgrounding, member/household switches and manual editing invalidate outstanding callbacks.
- The location card explains denial/permanent denial, disabled location, unavailable provider and timeout. Manual entry and questionnaire saving remain available. Write state remains explicit Idle/Saving/Saved/Failed, including failed manual writes.
- Manual drafts use SavedStateHandle. Invalid finite bounds focus the first invalid field. A manual correction replaces measured accuracy with null and uses the entry time; the UI labels it Manually corrected.
- Existing Room v3 coordinate columns are reused. New writes validate bounds, accuracy/source consistency and positive timestamps, then load the latest full record under the repository write mutex. Read/write errors become Failed while coroutine cancellation propagates; the manual draft remains available for retry. Archived records refuse coordinate writes. No migration or destructive fallback was added.

The framework provider uses requestLocationUpdates and rejects measurements preceding the request. Android documents that [getCurrentLocation can return a recent past fix](https://developer.android.com/reference/android/location/LocationManager); accepting it without checking age would not prove a newly acquired measurement. Coarse access uses an available fused/network provider, and the UI describes device fixes rather than promising GPS-only acquisition.

Current provenance is inferred from accuracy nullability using the existing v3 columns. Older rows retain their stored values; the app cannot recover an unknown historical source or capture time. The stronger source/time validation applies to new coordinate writes.

## Reproduction

From `android-native/`, build the isolated artifacts:

```powershell
rtk proxy ./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug -PisolatedTestApp=true --no-daemon --console=plain
```

Run the full matrix from the repository root:

```powershell
rtk proxy powershell -NoProfile -File tools/verify-d15-device.ps1 -DeviceSerial e7d5dc18
```

The harness preflights permission control, retains logs and screenshots, checks source identity, and attempts every device-setting restoration even if one command fails. A failed or partial restoration rejects acceptance. Use `adb devices -l` through RTK to select a different authorized serial if needed. `-RegressionOnly` (with optional `-ManualFallbacks`) reruns the non-permission subset without changing permission grants.

The final [repository checks](day15/repository-checks.txt) pass: documentation/JSON/local links, all 18 generated questionnaire definitions, board dependency/Done/WIP/persistence/mobile-layout checks and `git diff --check`. The board retains D15 Done with all three checklist items checked.
