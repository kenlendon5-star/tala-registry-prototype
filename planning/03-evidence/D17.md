# D17 — Export records on Android

Implemented and verified on 23 October 2026 on the Android 17 / API 37 emulator using the isolated `ph.tala.registry.d08test` debug application (version `0.6.0`, versionCode `6`). All records and data in the tests are fictional.

## Delivered

- A Reports screen lets the user select one or more households and creates `tala-backup-YYYYMMDD-HHmm.json` through Android's Storage Access Framework; canceling the document picker never starts an export.
- `BackupExporter` emits a versioned UTF-8 JSON document containing only the selected records, their UUID identities, answers, visits, coordinates, and valid embedded photo/signature bytes.
- Attachments that are missing, empty, or larger than 5 MiB are skipped and reported. JSON is written through a 50 MiB-limited staging file and copied to the selected destination only after the complete export succeeds, avoiding a second full in-memory copy and incomplete files caused by size rejection.
- The documented `backup-v1` schema and fictional example now match the fields actually stored by the Android app. The D18 restore workflow remains intentionally out of scope.
