# D13 — Finish interviews and callbacks

**Status: Done — 18 October 2026.** App 0.5.0 (5), isolated package `ph.tala.registry.d08test`, OPPO CPH2529 physical phone `e7d5dc18`, Android 15 / API 35. The full acceptance below is from this current-build target-phone run. Earlier emulator attempts are diagnostics and partial regression only.

## Delivered and accepted

- Visit result/date and local callback scheduling; Callback list filter; no-respondent/refusal paths; reopening partial interviews retains saved answers. Notifications remain outside scope.
- Explicit **Record visit result** action appends dated visit history with outcome, callback, notes and recording order. Draft autosaves do not append events; repeating the latest identical action does not duplicate it. Earlier outcomes remain visible after later visits and database reopen.
- Room schema 3 and migration 2→3 preserve existing visit IDs/outcomes/callbacks and attachment references. Unknown legacy dates stay blank; no destructive fallback is configured. Version 1→2→3 reopening also passes.
- Review calculates readiness across all 18 sections, jumps to missing answers, and grants **Reviewed** only after complete answers and consent. Status/message explicitly describe local review. Refusal remains a draft even when its roster or other sections are ready.
- Drawn and typed signature modes; native drawing with Undo, Redo and Clear; saved app-private PNG preview/reopen. Undoing the last stroke removes the durable attachment/file, including when a save is queued. Replacing/removing a reviewed signature returns the interview to In progress.
- Refusal removes the drawn mark. A failed removal reports Failed, blocks leaving and retries with Save; a queued late save cannot restore a signature after refusal. Signature PNG orphans participate in normal startup recovery.
- Removed the stale in-app statement that signatures arrive in a later build; updated schema, coverage and requirement documentation.

Total instrumentation: **42 tests passed across nine invocations**. Earlier failures and interrupted logs remain in `day13/prior-failed-*`. The initial review found two stale progress assertions (roster omitted), metadata-only signature evidence and last-stroke undo retaining the saved mark. These are corrected and tested. Visual inspection of the first fully passing OPPO run found low contrast on the live signature pad in dark mode. Its canvas now has the same white background as the saved PNG; final acceptance uses the rebuilt app with that correction. Native tests now wait for the actual asynchronous review/form transition, observe progress text in the unmerged semantics tree, and use the app's visible Back button for callback navigation; system Back remains covered by ShellDeviceTest. The existing editing test now polls for the transiently absent save-status node instead of throwing during that wait; its Saved assertion and five-second timeout are unchanged. Calendar tests also wait for dialog controls and Activity window focus before continuing; date, cancellation and appointment assertions remain unchanged. Household creation also awaits the generated display code from the Room observer before asserting identity and recreation; the Saved acknowledgement alone does not imply that separate observer has rendered. On the OPPO, a fast form-entry run missed the educational-assistance selection after keyboard-driven layout changes. The test now closes the keyboard and waits for its inset to disappear before moving to another control, checks the selection immediately, and reports section/member validation errors explicitly. A Windows read/write lock interrupted an earlier log capture; the runner now holds a shared streaming writer so live diagnostics cannot interrupt evidence capture. An early build overlapped implementation edits and failed compilation against older compiled classes; acceptance uses the later stable-source build and full device harness.

The emulator also showed a System UI ANR that blocked settings and window focus. Its observed hierarchy is retained in `day13/systemui-anr-preflight.xml`. Data-preserving restarts and a cold start were used; the settings preflight selects the observed Wait control if that specific OS dialog appears. The emulator launcher needed process-scoped SDK paths pointing to its existing image; no global SDK configuration was changed. Idle build daemons were stopped before device verification to reduce memory pressure. After repeated boot-time System UI failures, the emulator was cold-started with 1536 MB RAM and two cores. The observed Close app control recovered the failed System UI process, and Gboard settings were then verified accessible for subsequent emulator attempts. The emulator was interrupted before full acceptance; the final full acceptance uses the connected OPPO. The settings preflight now waits for the physical-keyboard submenu and toggle state before continuing. These are environment diagnostics, not passing app-test results.

## Reproduce

From `android-native/`:

```powershell
rtk proxy ./gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest -PisolatedTestApp=true --console=plain
```

From the repository root with the selected device unlocked:

```powershell
rtk proxy powershell -NoProfile -File tools/verify-d13-device.ps1 -DeviceSerial e7d5dc18
rtk proxy node tools/port-native-questionnaire.cjs --check
rtk proxy node planning/02-progress/verify-board.cjs
rtk proxy node tools/check-docs.cjs
```

The normal package and its data are preserved. The harness restores keyboard, screen timeout and stay-awake settings on the tested phone. `-SkipRegression` is a focused diagnostic run and does not establish the full acceptance above. Use `-DeviceSerial emulator-5554` for second-configuration follow-up.
