## Implementation

- **Map surface**: osmdroid 6.1.20 (Apache-2.0, no API key, no Play Services) renders OpenStreetMap Mapnik tiles over HTTPS with "© OpenStreetMap contributors" visible; the tile provider sends an identifying User-Agent and caches tiles only in the app-private cache directory. No offline tile packs are bundled or downloaded.
- **Permissions**: `INTERNET` and `ACCESS_NETWORK_STATE` exist solely for tile fetching and offline detection; a shell device test enforces that exact allow-list, and there is no backend, analytics or record data in any URL.
- **Pins and extent**: registry households plot as pins over the prototype's working extent (11.0116,124.5971 – 11.0236,124.6091, zoom 16–19) with the boundary still labeled approximate. Out-of-area coordinates are retained, flagged in the list and never re-center the map; new pins must land inside the extent and out-of-extent saves are rejected while keeping the draft.
- **Manual pin adjustment**: select a household, adjust by tapping/dragging or typing exact values; the draft survives activity recreation through SavedStateHandle and saving records Manual provenance (accuracy cleared, entry time recorded) through the same repository write path as the location card.
- **Offline fallback**: airplane mode or lost connectivity switches the same screen to an extent-accurate Web Mercator plot (graticule, accuracy circles, selection) labeled "Basemap unavailable offline — saved coordinates stay plotted and editable". Reads always come from Room, so no missing tile can make a saved coordinate inaccessible; external hand-off links embed coordinates only and degrade gracefully when no map app resolves the intent.
