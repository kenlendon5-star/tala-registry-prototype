# D06 — Connect native editing and saves

Implemented and verified on 12 October 2026. Day 6's editing and saves slice is complete on OPPO CPH2529, Android 15 / API 35, using app version 0.4.0 (versionCode 4).

## Delivered

- **Native Compose Edit Screens**:
  - `HouseholdEditScreen`: Form for creating or editing household head name, address/purok, visit status, and reversible archiving/restoration.
  - `MemberEditScreen`: Form for adding or editing a household member's full name, with deletion confirmation dialog that removes member-scoped answers.
  - Shared `SaveStatusLine`: Consistent status indicator displaying `Idle`, `Saving...`, `Saved on this device`, or `Could not save on this device` across screens.

- **ViewModel Save & Resume Flows**:
  - `HouseholdEditViewModel` & `MemberEditViewModel`: StateFlow-backed ViewModels collecting repository state and user drafts. Unsaved edits and record identity (UUIDs) are preserved across process death using `SavedStateHandle`.
  - Identity protection: Retrying a failed create or save updates the existing record ID rather than duplicating records.

- **Repository & Persistence Layer**:
  - `HouseholdRepository` & `RoomHouseholdRepository`: Reactive reads (`Flow<List<Household>>`), snapshot transactions, and `WriteResult` error handling.
  - Verification that two households do not overwrite one another and display codes (`HH-00001`, `HH-00002`) remain unique and sequential.
  - Reversible archiving: `setArchived(id, true)` keeps the record, members, and answers stored while marking `archivedAt` timestamp.
