Release scope, capacity and architecture

Native implementation: Compose screens → ViewModels / StateFlow → repositories → Room DAOs. Keep form rules in testable Kotlin. Use app-private attachment files, Android photo/document pickers and a native map/location integration. Start with a single app module and organize by feature. The browser prototype defines expected behavior; its DOM and JavaScript are rewritten.

Schedule risk: This assumes an experienced Kotlin developer. If the reusable form renderer and durable household/member slice are not demonstrated by Day 7, re-estimate immediately. Production accounts, cloud sync and field deployment are outside this month's acceptance scope.

Daily cadence and kanban rules

Release gate: The exact signed APK must pass fresh install, upgrade, offline interview, all 18 sections, permission denial, backup/restore and zero crash/data-loss/required-flow blockers. Deliver source, build instructions, capstone report, test/UAT evidence, user guide and ownership records. If a gate fails, hold release and revise the date.

Tracking: Checklists record work, and notes record acceptance evidence or blocker owner/next action. Dates do not move automatically when a card is blocked. A Done card requires all tasks, evidence and completed dependencies. Reopening an upstream card flags its dependents for review. Exported progress is a local JSON backup; it does not update the Markdown baseline.
