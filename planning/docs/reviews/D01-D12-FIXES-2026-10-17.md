The concurrent signature changes initially had missing imports/function arguments and a progress calculation that counted member sections as ready when the roster was empty. Minimal compilation repairs were applied. Progress now counts the actual 18 sections, including roster, and only counts member sections when members exist and all their forms validate. The lifecycle test fixture now supplies all required education answers. This compatibility work does not complete D13 callback/history/signature acceptance.

Keyboard investigation confirmed the emulator's Gboard “Show on-screen keyboard” switch was off even when the legacy secure setting was enabled. The Android 16+ Gboard setting change is documented in [Chromium's primary test-infrastructure change](https://chromium.googlesource.com/chromium/src/+/613ca493b9e14cb4df5e715507bcfd9eb560d52f). The harness locates the actual UI controls and restores the original switch value; it does not edit private preferences or weaken the app assertion. An emulator System UI ANR was also captured, followed by a data-preserving emulator restart.

## Boundaries

- Normal application data is preserved: instrumentation uses `ph.tala.registry.d08test` and dedicated fixture databases.
- Workspace restoration is tested through a real Android Bundle/Parcel, a destroyed/fresh ViewModel and Room. It is a controlled restoration test, not an actual OS-kill test. Separate native scenarios do force-stop/relaunch to verify confirmed saved answers.
- The target OPPO phone must rerun the changed flows when connected; the API 37 emulator supplies the second configuration. Full two-configuration release regression remains D22/D28.
- Export/restore, GPS/maps, full accessibility/performance, UAT and signing remain later gates. No database schema migration or connected backend is introduced here.
- Existing untracked signature work and unrelated connector configuration are preserved. No automatic commit, deployment or production-data operation is performed.
